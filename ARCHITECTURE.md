## 1. Что делает проект — простыми словами

Пользователь загружает своё CV в формате PDF или DOCX. Система читает его, отправляет в Claude (AI от Anthropic), и через 15–30 секунд выдаёт:

- **Seniority Score** — оценка уровня от 0 до 100 (Intern → Principal)
- **Зарплатный диапазон** — сколько ты стоишь на чешском IT рынке в CZK
- **План роста** — 3–5 конкретных действий чтобы зарабатывать на 30% больше

Всё это происходит через **4 последовательных запроса к AI** — каждый следующий строится на результате предыдущего. Это и есть Chain of Thought.

## 2. Из каких частей состоит

Проект состоит из **двух отдельных программ** которые запускаются одновременно:

```
┌─────────────────────────────────────────────────────────────┐
│  БРАУЗЕР пользователя                                        │
│  Открывает http://localhost:8501                             │
└──────────────────────┬──────────────────────────────────────┘
                       │ пользователь загружает файл
                       ▼
┌─────────────────────────────────────────────────────────────┐
│  FRONTEND — Streamlit  (порт 8501)                          │
│                                                             │
│  Это визуальная часть — то что видит пользователь.          │
│  Написана на Python с библиотекой Streamlit.                │
│  Файл: frontend/streamlit_app.py                            │
│                                                             │
│  Что делает:                                                │
│  • Показывает форму загрузки файла                         │
│  • Отправляет файл на Backend                               │
│  • Показывает прогресс в реальном времени                   │
│  • Рисует результаты в 4 вкладках                           │
└──────────────────────┬──────────────────────────────────────┘
                       │ отправляет файл и получает события
                       ▼
┌─────────────────────────────────────────────────────────────┐
│  BACKEND — FastAPI  (порт 8000)                             │
│                                                             │
│  Это "мозг" системы — пользователь его не видит.            │
│  Написан на Python с библиотекой FastAPI.                   │
│  Файл: app/main.py                                          │
│                                                             │
│  Что делает:                                                │
│  • Принимает файл от Frontend                               │
│  • Извлекает текст из PDF/DOCX                              │
│  • Запускает 4-шаговый pipeline                             │
│  • Отправляет результаты обратно                            │
└──────────────────────┬──────────────────────────────────────┘
                       │ отправляет запросы
                       ▼
┌─────────────────────────────────────────────────────────────┐
│  Claude API  (Anthropic сервера, интернет)                  │
│                                                             │
│  Платный AI сервис. Мы платим за каждый запрос.             │
│  Модель: claude-sonnet-4-5                                  │
│  Принимает текст → возвращает JSON с анализом               │
└─────────────────────────────────────────────────────────────┘
```

**Почему два отдельных процесса, а не один?**
Это стандартный паттерн в веб-разработке: Frontend отвечает за внешний вид, Backend — за логику. Их можно деплоить отдельно, масштабировать независимо, и заменить Frontend (например на React) не трогая Backend.

## 3. Как данные проходят через систему

Пошагово от загрузки файла до результата:

```
1. Пользователь выбирает файл CV.pdf в браузере
        ↓
2. Streamlit читает байты файла (file.getvalue())
        ↓
3. Streamlit отправляет POST запрос на http://localhost:8000/analyze/stream
   Тело запроса: multipart/form-data с файлом внутри
        ↓
4. FastAPI получает запрос, читает файл
        ↓
5. cv_parser.py извлекает текст из PDF/DOCX
   PDF → pdfplumber читает текстовый слой
   DOCX → python-docx читает параграфы
        ↓
6. Чистый текст CV идёт в pipeline (4 шага, каждый = 1 запрос к Claude)
        ↓
7. После каждого шага FastAPI отправляет "событие" обратно в Streamlit
   Streamlit обновляет прогресс-бар: 10% → 35% → 60% → 85% → 100%
        ↓
8. После шага 4 — финальный результат отправляется как JSON
        ↓
9. Streamlit рисует 4 вкладки с результатами
```

## 4. Chain of Thought Pipeline — 4 шага

**Chain of Thought** (Цепочка мыслей) — это техника работы с LLM, где вместо одного большого запроса мы делаем несколько последовательных, и каждый следующий видит результат предыдущего.

**Почему не один запрос?**
Если спросить AI "Проанализируй CV и дай всё сразу" — качество падает. AI пытается думать о слишком многом одновременно. Разбивка на шаги = лучшие результаты + легче отлаживать что пошло не так.

---

### Шаг 1 — Извлечение фактов
**Файл:** `app/pipeline/step1_extract.py`

```
Входит:  сырой текст CV (просто строка)
Выходит: структурированный объект CVFacts
```

Мы говорим Claude: *"Прочитай этот текст и извлеки факты. Только факты — не оценивай."*

Результат выглядит так:
```json
{
  "full_name": "Jan Novák",
  "total_years_experience": 3.5,
  "tech_skills": [
    {"name": "Python", "years_experience": 3.0},
    {"name": "C#", "years_experience": 2.0}
  ],
  "soft_skills": ["communication", "teamwork"],
  "education_level": "bachelor",
  "industries": ["saas", "fintech"],
  "notable_achievements": ["Telegram bot с 2000 пользователями"]
}
```

**Почему отдельный шаг?** Потому что извлечение фактов и их оценка — разные задачи. Смешивать их = хуже качество.

---

### Шаг 2 — Оценка сениорити
**Файл:** `app/pipeline/step2_seniority.py`

```
Входит:  CVFacts из шага 1
Выходит: SeniorityEvaluation со score 0–100
```

Мы говорим Claude: *"Вот факты о кандидате. Оцени его уровень по шкале 0–100 и объясни почему."*

Claude видит не сырой текст CV, а уже структурированные данные из шага 1. Это чище и точнее.

Критерии оценки которые мы задаём в промпте:
- Сколько лет реального опыта (не просто "знаю Python", а работал с ним)
- Масштаб проектов (личный проект на GitHub vs продакшн система с нагрузкой)
- Командный опыт (работал один или в команде)
- Глубина в одной технологии vs поверхностное знание многих

Шкала:
| Уровень | Очки | Значение |
|---------|------|---------|
| Intern | 10–29 | Студент / первый опыт |
| Junior | 30–49 | До 2 лет опыта |
| Mid | 50–69 | 2–5 лет, самостоятельный |
| Senior | 70–84 | 5+ лет, ведёт других |
| Lead | 85–94 | Архитектурные решения |
| Principal | 95–100 | Эксперт уровня компании |

---

### Шаг 3 — Прогноз зарплаты
**Файл:** `app/pipeline/step3_salary.py`

```
Входит:  SeniorityEvaluation (внутри которого лежит CVFacts)
Выходит: SalaryEstimate с диапазоном в CZK
```

Интересная деталь: в системный промпт мы **вставляем реальные данные рынка** из файла `app/data/salary_data.py`. Claude не выдумывает цифры — он видит таблицу чешских зарплат и рассуждает внутри неё.

```python
# Данные которые мы передаём Claude в промпте:
CZ_SALARY_RANGES = {
    "intern":    {"min": 18_000, "median": 22_000, "max": 28_000},
    "junior":    {"min": 30_000, "median": 42_000, "max": 55_000},
    "mid":       {"min": 55_000, "median": 70_000, "max": 90_000},
    "senior":    {"min": 85_000, "median": 105_000, "max": 135_000},
    ...
}

# Мультипликаторы за востребованные скиллы:
SKILL_MULTIPLIERS = {
    "llm": 1.18,            # +18% если знаешь LLM
    "machine_learning": 1.15,
    "cloud_aws": 1.12,
    "python": 1.05,
    ...
}
```

**fit_score** — отдельная метрика 0–100, показывает насколько скиллы кандидата совпадают с тем что рынок платит дорого прямо сейчас.

---

### Шаг 4 — Рекомендации
**Файл:** `app/pipeline/step4_recommendations.py`

```
Входит:  краткая выжимка из шага 3 (~800 токенов)
Выходит: GrowthRecommendations — 3–5 конкретных действий
```

Claude знает текущий уровень кандидата, его слабые места, и рыночные данные. На основе этого генерирует конкретный план — не "учи больше", а "получи AWS сертификат за 4 месяца, это даст +12% к зарплате".

**Важный технический момент — slim context:**
К шагу 4 мы накопили большой объект данных (CVFacts → SeniorityEvaluation → SalaryEstimate). Если передать его целиком, это ~3500 токенов только на вход. При лимите в 4096 токенов на ответ, Claude не успевает написать полный ответ и обрезает JSON на середине — это вызывает ошибку.

Решение: передаём только 6 ключевых полей вместо полного объекта:
```python
slim_context = {
    "level": seniority.level,
    "score": seniority.score,
    "weaknesses": seniority.weaknesses,
    "top_skills": salary.top_skills_driving_salary,
    "median_czk": salary.estimated_range.median_czk,
    "target_czk": int(salary.estimated_range.median_czk * 1.3),
}
```
Это ~800 токенов → остаётся ~3200 токенов на ответ → JSON не обрезается.

## 5. Технологии и зачем каждая

### Python
Язык программирования всего проекта. Выбран потому что:
- Лучшая экосистема для AI/ML библиотек
- FastAPI и Streamlit — обе библиотеки на Python
- Anthropic SDK (библиотека для Claude) — тоже Python

---

### FastAPI
**Что это:** библиотека для создания REST API на Python.
**Зачем нужен API:** Frontend и Backend — разные процессы. Им нужен способ общаться. API — это набор "эндпоинтов" (адресов) которые принимают запросы и возвращают данные.

Наши эндпоинты:
```
POST /analyze/stream  ← загрузить CV, получить живой поток событий
POST /analyze         ← загрузить CV, ждать полного ответа
GET  /health          ← проверить что backend работает
GET  /salary-benchmarks ← получить данные чешского рынка
```

FastAPI автоматически генерирует документацию: http://localhost:8000/docs — можно зайти и попробовать API вручную прямо в браузере.

---

### Streamlit
**Что это:** библиотека которая превращает Python скрипт в веб-приложение.
**Почему не React/Vue:** Streamlit в 10 раз быстрее для прототипов и data-приложений. Пишешь Python — получаешь красивый UI. Минус — меньше гибкости для сложных интерфейсов.

```python
# Весь UI это просто Python код:
st.markdown("## Результат")
st.progress(85)
st.bar_chart(data)
```

---

### Pydantic v2
**Что это:** библиотека для валидации данных в Python.
**Зачем:** Claude возвращает JSON. Нам нужно убедиться что в нём есть все нужные поля и правильных типов. Pydantic делает это автоматически.

```python
# Описываем что ожидаем получить:
class SalaryRange(BaseModel):
    min_czk: int
    median_czk: int
    max_czk: int

    @model_validator
    def check_order(self):
        if self.min_czk > self.median_czk:
            raise ValueError("min не может быть больше median")
```

Если Claude вернёт `min_czk = 90000` и `median_czk = 50000` — Pydantic бросит ошибку, и мы не покажем пользователю бессмысленные данные.

---

### Claude API (Anthropic)
**Что это:** платный сервис AI. Мы отправляем текст, получаем ответ.

Ключевые параметры:
- `model = "claude-sonnet-4-5"` — конкретная версия модели (sonnet = баланс скорости и качества, дешевле opus)
- `max_tokens = 4096` — максимальная длина ответа (токен ≈ 0.75 слова)
- `timeout = 60.0` — если Claude думает дольше 60 секунд, запрос отменяется

---

### pdfplumber + python-docx
Две библиотеки для чтения файлов:
- `pdfplumber` — читает PDF, умеет работать с таблицами в CV
- `python-docx` — читает DOCX (формат Word)

Проблема со сканами: если CV — это фотография/скан, pdfplumber извлечёт 0 текста (он читает текстовый слой, а не картинку). Мы проверяем: если текста меньше 50 символов — показываем ошибку "похоже это скан, нужен текстовый PDF".

---

### pytest
Библиотека для автоматических тестов. 37 тестов проверяют что код работает правильно.

Зачем тесты:
- Если изменишь код — сразу увидишь что сломалось
- Работодатель видит что разработчик думает о надёжности
- Можно запустить `./run.sh test` и убедиться что всё ок перед деплоем

---

### Docker + docker-compose
**Docker** — упаковывает приложение со всеми зависимостями в изолированный контейнер. Работает одинаково на любом компьютере.

**docker-compose** — запускает несколько контейнеров вместе:
```yaml
services:
  api:   # Backend на порту 8000
  ui:    # Frontend на порту 8501
```

Команда `docker-compose up` — поднимает оба сервиса, они автоматически видят друг друга по имени сервиса (`http://api:8000` вместо `http://localhost:8000`).

## 6. Как работает LLM клиент

**Файл:** `app/utils/claude_client.py`

Это самый сложный файл — обёртка над Anthropic SDK. Решает три проблемы:

### Проблема 1: Claude иногда возвращает не чистый JSON

Мы просим Claude вернуть JSON. Но иногда он отвечает так:
```
Вот результат анализа:
```json
{"level": "mid", "score": 55}
```
Надеюсь это поможет!
```

Функция `_clean_raw()` убирает всё лишнее:

**Шаг А** — убираем markdown-обёртку ` ```json ... ``` `:
```python
if raw.startswith("```"):
    raw = raw.split("```", 2)[1]   # берём что между первой и второй ```
    if raw.startswith("json"):
        raw = raw[4:]               # убираем слово "json"
```

**Шаг Б** — находим JSON по фигурным скобкам (brace-matching):
Ищем первую `{`, потом считаем вложенность скобок. Когда счётчик вернулся к 0 — нашли конец JSON.
```python
depth = 0
for каждый символ:
    если '{' → depth + 1
    если '}' → depth - 1
    если depth == 0 → нашли конец JSON, берём этот кусок
```

### Проблема 2: Как заставить Claude вернуть нужную структуру

В системный промпт мы вставляем JSON Schema — описание того какой формат мы ожидаем:
```
You MUST respond with valid JSON matching this exact schema:
{"level": "string (intern|junior|mid|senior|lead|principal)", "score": "integer 0-100", ...}
```

### Проблема 3: Сеть может упасть

2 попытки. Если первая не получила валидный JSON — пробуем ещё раз. Если обе упали — исключение с текстом ответа для дебага.

## 7. Как работает живой прогресс-бар (SSE)

**SSE = Server-Sent Events** — технология где сервер отправляет данные клиенту по одному, не закрывая соединение.

**Аналогия:** как SMS сообщения. Сервер пишет тебе сообщения одно за другим пока думает. Ты читаешь каждое как только оно пришло — не ждёшь пока придут все.

**Альтернативы которые мы не использовали:**
- **Polling** — Streamlit каждые 2 секунды спрашивает "ну как там?" — расточительно
- **WebSocket** — двустороннее соединение, избыточно (нам данные нужны только в одну сторону)
- **SSE** — сервер пишет, клиент читает. Просто, надёжно, идеально для нашего случая.

**Как реализовано:**

Backend (FastAPI) — генератор который `yield`-ает события:
```python
def event_stream():
    # Шаг 1 начался:
    yield 'data: {"step": 1, "progress": 10, "label": "Extracting..."}\n\n'
    cv_facts = step1_extract.run(cv_text)   # ← Claude думает здесь (5-10 сек)

    # Шаг 2 начался:
    yield 'data: {"step": 2, "progress": 35, "label": "Evaluating..."}\n\n'
    seniority = step2_seniority.run(cv_facts)  # ← Claude думает здесь
    ...
```

Frontend (Streamlit) — читает поток и обновляет UI:
```python
for line in response.iter_lines():
    event = json.loads(line[6:])           # парсим JSON
    progress_bar.progress(event["progress"])  # обновляем полоску
    steps_box.markdown(render_steps(...))     # обновляем список шагов
```

Прогресс: **10% → 35% → 60% → 85% → 100%**

## 8. Pydantic — зачем нужны модели данных

**Файл:** `app/models/pipeline_models.py`

Pydantic — это система типов для данных. Думай о ней как о контракте: "данные ДОЛЖНЫ выглядеть вот так".

**Без Pydantic** мы работали бы с сырым словарём:
```python
data = {"score": "пятьдесят пять"}  # строка вместо числа — никто не заметит
print(data["score"] + 10)           # ошибка в рантайме
```

**С Pydantic:**
```python
class SeniorityEvaluation(BaseModel):
    score: int   # ТОЛЬКО число

SeniorityEvaluation(score="пятьдесят пять")  # ← сразу ошибка при создании объекта
```

Цепочка моделей в проекте:
```
CVFacts
  └── TechSkill (список)

SeniorityEvaluation
  └── cv_facts: CVFacts

SalaryEstimate
  └── estimated_range: SalaryRange
  └── market_range_for_level: SalaryRange
  └── seniority_eval: SeniorityEvaluation

GrowthRecommendations
  └── recommendations: list[Recommendation]  (1–5 штук)
  └── salary_estimate: SalaryEstimate

PipelineResult  ← финальный ответ API
  └── cv_facts, seniority, salary, recommendations
```

Каждая модель проходит через весь pipeline. К концу `PipelineResult` содержит все данные со всех 4 шагов.

## 9. Кэширование — почему не тратим деньги дважды

**Проблема:** Каждый вызов Claude стоит денег (~$0.01–0.05 за анализ одного CV). Если пользователь случайно нажал "Analyze" дважды на одном файле — плохо.

**Решение:** MD5 хеш файла как ключ кэша.

MD5 — алгоритм который превращает любые данные в короткую строку-"отпечаток":
```python
import hashlib
hashlib.md5(file_bytes).hexdigest()
# → "d8e8fca2dc0f896fd7cb4cb0031ba249"
```

Одинаковый файл → одинаковый хеш → берём результат из кэша, не идём в Claude.

```python
@st.cache_data         # декоратор Streamlit — кэшировать результат функции
def call_analyze(file_bytes, filename, api_key, _hash):
    # _hash — это MD5, Streamlit использует его как ключ кэша
    ...
```

Кэш живёт пока Streamlit запущен. Перезапуск — кэш очищается.

## 12. Вопросы на интервью и ответы на них

**Q: Почему 4 отдельных LLM вызова, а не один большой промпт?**

A: Chain of Thought — проверенная техника. Каждый шаг фокусируется на одной задаче: извлечение фактов, оценка, расчёт зарплаты, рекомендации. Когда модель пытается делать всё сразу — качество каждой части падает. Плюс при ошибке сразу видно на каком шаге она произошла.

---

**Q: Как ты гарантируешь что LLM вернёт правильный JSON?**

A: Три слоя защиты. Первый — в системный промпт вставляем JSON Schema, модель видит точный формат который ожидается. Второй — `_clean_raw()` убирает markdown-обёртку и извлекает JSON по brace-matching даже если вокруг есть лишний текст. Третий — Pydantic валидирует результат и бросает ошибку если данные не соответствуют схеме. При ошибке — retry, вторая попытка.

---

**Q: Почему SSE, а не WebSocket?**

A: WebSocket — двустороннее соединение, нужен когда клиент тоже отправляет данные в реальном времени (чат, игры). У нас только сервер пишет клиенту — результаты шагов. SSE проще, нативно поддерживается браузерами, и идеально для однонаправленного потока событий. FastAPI поддерживает SSE через `StreamingResponse`.

---

**Q: Как защищён API ключ?**

A: Ключ хранится в `.env` файле который добавлен в `.gitignore` — никогда не попадает в git. В `.env.example` (который в git) — только placeholder `sk-ant-your-key-here`. В продакшне ключ передаётся через переменные окружения, не хардкодится в коде.

---

**Q: Зачем кэш по MD5?**

A: Каждый вызов Claude стоит денег. Если пользователь загружает один и тот же файл дважды (случайно или чтобы проверить) — незачем платить снова. MD5 даёт одинаковый хеш для одинаковых байтов файла. Streamlit `@cache_data` хранит результат в памяти — повторный запрос возвращает его мгновенно без API вызова.

---

**Q: Почему на шаге 4 передаётся только часть данных?**

A: LLM имеет лимит токенов: `MAX_TOKENS=4096` — максимум что он может написать в ответе. Если в запросе уже 3500 токенов (полный объект со всеми вложенными данными) — на ответ остаётся только 596 токенов. JSON с рекомендациями не помещается, модель обрезает его на середине и мы получаем невалидный JSON. Решение — передать только 6 нужных полей (~800 токенов), остальное остаётся для ответа.
